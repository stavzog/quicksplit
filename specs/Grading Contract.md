# **Grading Contract:**

## **For a C (Pass)**

* **Documentation**: Completed PDF write-up, including needfinding results and initial algorithmic/affordance analysis.  
* **Dataset**: A valid dataset file containing between 10 and 999 entries.  
* **Repository**: A public GitHub Repo with a detailed README explaining how to run the software.  
* **Feature 1 (Logging)**: A working CLI feature that allows users to input expenses and save them to a local file.

## **For a B**

* **C-Tier Requirements**: All requirements for a C must be fulfilled.  
* **Scale**: A valid dataset file containing \<= 1,000 entries to test data structure scalability.  
* **API Detail**: A GitHub Repo that explicitly details our custom data structure's public API.  
* **Feature 2 (Settle Up)**: Implementation of a custom Directed Weighted Graph to calculate the most efficient way for group members to settle debts.

## **For an A**

* **B-Tier Requirements**: All requirements for a B must be fulfilled.  
* **Usage Examples**: A GitHub Repo that provides clear, practical usage examples for all public methods.  
* **Software Quality**: Code must adhere to professional style guidelines, including comprehensive JavaDocs and comments.  
* **Feature 3 (Multi-Currency)**: The tool can handle logging expenses and showing settle-up results in multiple currencies 

## **For an A+**

* **A-Tier Requirements**: All requirements for an A must be fulfilled.  
* **Extra Option (Networking)**: Integration with an external REST API (JSONBin.io) to support multi-user "Cloud Room" synchronization without requiring user accounts. This feature is outside the standard scope of the class and addresses our core human-centered design goals.
